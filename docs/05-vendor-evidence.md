The [QuSecure release](https://www.qusecure.com/qusecure-named-as-global-product-leader-in-post-quantum-cryptography-industry-by-frost-sullivan/) is first-party evidence of what the company reports. An award and a vendor's architecture description are not a cryptographic validation or an independently verified government authorization. The current [Quranium DeQUIP page](https://www.quranium.org/dequip) is evidence of present positioning; it does not prove the source deck's Layer-2 claim or unconditional security. Neither source is used as a blanket security guarantee.

## Due-diligence questions that would improve this comparison

1. Which exact algorithm, parameter set, implementation version and protocol provide which service: confidentiality, authentication or signatures?
2. What security boundary is evaluated: library, appliance, orchestration control plane, endpoints, network or blockchain?
3. Which failures remain possible through keys, randomness, authentication, software updates, dependencies or operations?
4. What independent evaluation is available, with scope, date, version and reproducible method?
5. Can both systems be tested against the same use case? If not, state why a ranking is inappropriate.
6. Does a cited deployment mean a demonstration, pilot, operational system, procurement or authorization? Identify the actual program and relevant evidence.

These are follow-up questions, not questions the contributor is claimed to have asked. No messages have been sent to vendors.

## Reversal condition

A versioned technical architecture or independent report could support a narrower claim. Record it as a new source, cite the exact section, and update the particular claim it supports. Lack of evidence in this repository does not show a product is insecure or a company is deceptive.
